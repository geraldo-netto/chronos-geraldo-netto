## Clean categories

Verified with no findings on the 2026-07-12 (third-pass) rescan:

- **Secrets, TLS, injection.** No API key, token or credential in the tree. Every endpoint `https://`, with the https→http downgrade cancelled on Soup's `restarted` signal *before* the redirected request goes out. No `set_markup`/`use_markup` anywhere — every remote and EDS string reaches a non-parsing sink. Both inline-`style` sinks pass through `styleUtils.safeCssColor`, whose anchored allowlist admits no `;` and no `url(`. Every subprocess is argv-form. No `eval`/`Function`/dynamic import; no SQL. Every query parameter is `encodeURIComponent`'d, and query strings are stripped from all log lines.
- **Untrusted-input bounds** (except the row count, T361): declared *and* actual body size capped at 4 MiB; non-object JSON coerced to `null`; holiday names clamped to 300 chars, event summaries to 300, clock labels to 24, panel suffix to 48; geocode cache 16, month memo 32, cached countries 4, holiday spans 366 days, years pruned to ±1.
- **Cache file safety.** Fixed filename under `GLib.get_user_cache_dir()` — no user or remote input in the path, so no traversal; dir created `0700`; both writers pass `REPLACE_DESTINATION`, so a planted symlink is replaced, not followed (though nothing tests that — T371); every row re-validated on load, including the future-stamp attack on `stale()`.
- **Untrusted EDS data.** Unix times range-checked before `GLib.DateTime.new_from_unix_local`; `EventDataList._events` is `Object.create(null)`, so a `__proto__` UID cannot corrupt the index; a bad event is skipped, not thrown.
- **Consent and egress defaults.** Both networked features are off by default (`show-weather: false`, `country: "none"`), unknown countries are re-asserted to `none` at startup, and the world-clock **display name never leaves the machine** — only the IANA-derived city is geocoded. (The one live hole is T353, where opting *out* does not take effect. The disclosures were English-only for every non-English user until T273 closed.)
- **Generation guards.** `WeatherProvider._request_generation`, `CityWeatherProvider._isCurrent`, `Enrico._isCurrentPlace`, the fallback adapter's liveness check and the annotator's `_holiday_update_generation` all correctly abandon superseded in-flight work. (The one gap is the *inflight-map* bookkeeping around them — T352.)
- **Teardown.** Every `timeout_add`/`idle_add` id is stored and removed on a path reachable from `on_applet_removed_from_panel`, all three Soup sessions are `abort()`ed, `EventsManager.destroy()` cancels its cancellable *before* dropping the proxy, and each teardown step is isolated so one throw does not strand the rest. (The two stragglers are T389 and T390.)
- **The 42-cell grid.** Built once, mutated in place, with `rendered_style` / `dot_key` / `accessible_name` all diffed before writing; the month window (42 dates, 42 keys, 42 accessible strings) is memoised per month/week-start; dot metrics are hoisted out of `allocate` onto `style-changed`. The remaining costs are the tooltip's missing guard (T379) and the spurious rebuild from the locale listener (T380).
- **The 1 Hz closed-menu tick.** No clock entries are built when `panel_clocks == 0`; the panel label, accessible name, day and date labels are all memoised against the last rendered string; `getFormattedToday()` is keyed on year + day-of-year and rolls at *local* midnight. `CinnamonDesktop.WallClock` only emits `notify::clock` when the rendered string changes, so the label is not rewritten every second.
- **DST and date math.** `_buildDays`, `expandHoliday` and `_formatJsDate` all anchor at 12:00 before day arithmetic; `holidaySpanDays` uses `Date.UTC(…, 12)`. (Nothing *tests* a DST transition — T374.)

Every class `stylesheet.css` defines has an actor that applies it, and the classes actors use but the sheet does not define are Cinnamon *theme* classes (confirmed present in `calendar@ccprog`), not missing ones.
- **The pot is fresh.** Regenerated from scratch: identical msgid set, `msgcomm --unique` empty in *both* directions. Nothing in the source is unextractable — every schema string, both `metadata.json` strings, and correct `ngettext` plurals. The weather condition words *look* untranslatable as bare English constants but are re-wrapped through lookup tables at `appletPanelStatus.js:27-47`. `MISSING_PYTZ_WARNING` is correctly left unwrapped (log-only). The `.po` files were the problem, not the pot; both are now complete (T355, T273).
- **No wrong translations.** Across all 15 catalogs: zero printf/strftime specifier mismatches between msgid and msgstr, zero markup in a msgstr its msgid lacks, correct `Plural-Forms` headers, `msgfmt -c` clean.
- **README accuracy.** Every factual claim re-checked against source and correct: all 11 defaults, the 8-clock cap (JS *and* Python agree), the 30-min refresh, the 1-hour "last known" threshold, the 50-day holiday period, the cache path, all three provider orders, the panel format, the keyboard map, the `multiversion` layout. The `5.4/icon.png` duplicate is the repo-wide multiversion convention (`calendar@ccprog`, `weather@mockturtl`, `sound150@claudiux` all do it) — **not** a defect.

## Recorded decisions

| id | decision |
|----|----------|
| D02 | **Keep the widened export surface.** About 60 of the 243 exported names have no cross-module consumer: they are used inside their own file and otherwise only by `test/`. None of it is dead — every one is alive at runtime — so this is a question of policy, not a list of deletions, and the policy is: the applet runs inside a compositor, where a bug costs the user their whole desktop session, and its collaborators are DBus, three holiday services, two forecast services, two geocoders, a settings dialog in another process and a locale subprocess. Testing that through the composition root alone would mean driving the retry ladders, the generation guards and the cache-merge races from the outside, which is exactly the kind of test that is slow, flaky and does not say what broke. Revisit only if the exports start being consumed *outside* the tests. **Note the third pass draws a line this decision does not cover:** an export that exists for tests is fine (D02), but a *production field* that exists only so a test can read it (T391), and a *production fallback branch* that exists only because a mock has the wrong shape (T393, `worldclockData.js:52`), are not — those are the code bending to fit the test, which is the failure D02 was never meant to license. |
| D01 | Keep the six third-party endpoints (three holiday providers, two forecast providers, two geocoders) rather than dropping to a bundled data set or a single vendor. A bundled holiday table would go stale and cover far fewer countries, and a single provider would leave holidays broken whenever it is down — the fallback chain exists precisely because the primary is a hobbyist service. The risk is accepted with mitigations: both readouts are opt-in and default-off, responses are size-capped, holiday spans are bounded, payloads are shape-checked on the way in and on the way back out of the cache, colors are filtered before reaching inline styles, and no request URL is logged. (The residual gaps this pass found in those mitigations are T361 and T371.) Revisit if a provider domain changes hands. |
