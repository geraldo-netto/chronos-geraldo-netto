| T677 | decoupling; architecture / modularity / SOLID; state machine integrity; UI / UX | Medium | open | M | Decouple calendar browsing and selection from Evolution-event availability. | **[verified]** `events_enabled` is derived from `events_manager.is_active()` (`5.4/calendar.js:782-784`), whose state is false when **Show calendar events** is off, EDS is unavailable, or no calendars exist (`eventsManager.js:760-762`, `calendarServerConnection.js:185-187`). The same state is wired into `CalendarNavigationController` (`5.4/calendar.js:707-715`), which blocks every key, scroll, and header browse (`5.4/calendarNavigation.js:153-167,195-212,233-239`), while day clicks independently refuse at `5.4/calendar.js:385-390`. Thus an event-column integration toggle also locks the otherwise independent holiday calendar, contradicting README's standalone grid-navigation contract (`README.md:192,254-255`) and coupling presentation navigation to an optional provider's lifecycle. Split `canBrowse`/`canSelect` from `eventsAvailable` (or keep a displayed-month state separate from agenda selection), and cover holidays-only, events-disabled, no-calendars, and EDS-unavailable paths across mouse, keyboard, scroll, and header buttons. |
| T678 | wiring gaps; reliability / correctness | Low | open | M | Attribute world-clock weather to every provider that supplied the displayed readings. | **[verified]** `weatherSourceName()` prefers the unrelated panel-location provider and consults the city provider only when that name is blank (`5.4/appletPanelStatus.js:674-676`), then sends the result to the world-clock block (`:794-795`; port wiring in `5.4/applet.js:84`). The city model is also lossy: each successful city overwrites one global `_last_provider` while stored readings retain no provenance (`cityWeather.js:110-112,426-430`), although every city has an independent fallback outcome and a failed round can retain older readings. Thus displayed rows served by MET Norway/AviationWeather can announce only Open-Meteo (from the panel or the last city), and mixed-provider rows cannot be represented at all. Store provider with each city reading and render per-row credit or an aggregate of the distinct displayed sources; keep panel attribution separate and cover divergent panel/city, mixed-city, and retained-last-good outcomes. |
| T679 | state machine integrity; concurrency / races; security / privacy | Medium | open | S | Make the weather opt-out invalidate work immediately instead of after the settings debounce. | **[verified]** every weather-setting change, including `show-weather=false`, goes through `_queueWeatherRefresh()` (`5.4/applet.js:417-421,470-472`). `WeatherProvider.queue()` only replaces the debounce source (`weather.js:242-250`; `weatherScheduler.js:167-176`); it neither increments `_request_generation` nor stops the active periodic/retry sources until `schedule()` runs after the debounce (`weather.js:218-219`; `weatherScheduler.js:89-124`). During that interval an old timer can start a new provider request with its captured `showWeather: true`, and an old in-flight completion is still current. City weather already applies the new disabled state synchronously (`5.4/appletCoordinators.js:43-45,61-76`; `cityWeather.js:243-265`). Treat deactivation as a control transition: immediately invalidate the panel generation and stop its scheduler, reserving debounce for active edits; cover disabling during an in-flight request and immediately before periodic/retry callbacks. |
| T680 | architecture / modularity / SOLID; resource / lifecycle management; wiring gaps | Low | open | S | Tear down event UI subscribers before destroying their event producer. | **[verified]** the applet teardown destroys `AppletProviderLifecycle` before `AppletMenuBuilder`, `Calendar`, and `EventList` (`5.4/applet.js:552-568`). Provider teardown disconnects only its own two manager handlers and then calls `EventsManager.destroy()` (`5.4/appletLifecycle.js:423-433,459-469`); the menu builder and calendar do not detach their five remaining manager subscriptions until later (`5.4/appletMenuBuilder.js:237-249`; `5.4/calendar.js:771-774`). The builder explicitly relies on today's implementation emitting nothing during/after producer destruction (`5.4/appletMenuBuilder.js:175-180`), so lifecycle safety depends on an undocumented destruction side effect and a future terminal-state notification would reach UI consumers while their upstream services are already being dismantled. Reverse the dependency order—detach/destroy UI consumers first, then providers/events—and pin teardown when producer destruction emits or throws. |
| T681 | reliability / correctness; UI / UX | Low | open | S | Clamp calendar event-dot layout to a valid row capacity. | **[verified]** `CalendarGridView.allocateDotBox()` divides the allocated cell width by the theme-derived natural dot width and truncates it without a lower bound (`5.4/calendar.js:575-594`). If a theme makes a dot wider than its cell, `perRow` becomes zero; `rowDots` is then zero on every permitted row and no child is allocated (`:596-607`), so event markers silently disappear. A zero natural width also produces non-finite capacity and zero-width allocations, while `max-rows` is accepted without a positive-integer guard. Validate the theme metrics, clamp the effective capacity/row count, and cover zero-width and oversized-dot allocations. |

## Recorded decisions

| id | decision |
|----|----------|
| D01 | Keep the third-party endpoints rather than a bundled data set or a single vendor. A bundled table goes stale and covers fewer countries; a single provider breaks whenever it is down — the fallback chain exists because the primary is a hobbyist service. Risk accepted with mitigations (weather opt-in; one-time local-tzdata holiday default with visible third-party disclosure and explicit disable/override; size caps; bounded spans; shape checks in and out of cache; colour filtering; no URL logging). |
| D02 | **Keep the widened export surface.** ~80 exported names have no cross-module consumer — used inside their own file and otherwise only by `test/`. The applet runs inside a compositor where a bug costs the whole session; testing only through the composition root would be slow and flaky. **This does not license the inverse:** production must not bend to a test double's shape. |
| D03 | **`author` is the display name "Geraldo Netto", not the GitHub handle.** `info.json`/`package.json` use "Geraldo Netto"; `schema_static.test.js` asserts it. The Spices convention prefers the handle, but the display name is the maintainer's explicit choice. |
